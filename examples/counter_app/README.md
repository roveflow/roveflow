# counter_app — Roveflow example

A freshly-scaffolded Flutter counter app with Roveflow installed. Ships as
the reference install for the `roveflow init` flow.

## Run it locally

```bash
# From the repo root:
dart pub global activate --source path packages/roveflow
cd examples/counter_app
roveflow init            # materialises .claude/ + .mcp.json (all gitignored)
flutter pub get
flutter run -d <simulator-id>
```

The `.claude/skills/roveflow/`, `.claude/commands/roveflow.md`,
`.claude/agents/roveflow-runner.md`, and `.mcp.json` are **not** committed
— they're regenerated by `roveflow init` on demand. Only the hand-written
parts live in git: `lib/main.dart`, `lib/core/general_helpers/utils/navigation_util.dart`,
`lib/core/mcp/mcp_interaction_tools.dart` (with the `<your_app>` placeholder
pre-substituted for this example), `docs/roveflow/scenarios.md`, and `pubspec.yaml`.

You'll need to edit `.mcp.json` after init to point the
`flutter-inspector` `command` at your local `flutter_inspector_mcp` binary.

## What `roveflow init` wrote

- `.claude/skills/roveflow/` — the full skill (SKILL.md + 10 references)
- `.claude/commands/roveflow.md` — slash command
- `.claude/agents/roveflow-runner.md` — sub-agent body
- `lib/core/mcp/mcp_interaction_tools.dart` — MCP tools drop-in
- `.mcp.json` — flutter-inspector config
- `docs/roveflow/scenarios.md` — scenarios inventory (starter template, then
  replaced with counter-app cold-setup)

## What a user must do after `roveflow init`

1. **Wire main.dart** — add the `kDebugMode` block with
   `MCPToolkitBinding.instance.initialize()`,
   `MCPToolkitBinding.instance.initializeFlutterToolkit()`,
   and `await registerMcpInteractionTools()`.
2. **Substitute the `<your_app>` placeholder** in
   `lib/core/mcp/mcp_interaction_tools.dart`. The template imports
   `package:<your_app>/core/general_helpers/utils/navigation_util.dart`
   — replace `<your_app>` with the pubspec `name`.
3. **Provide a `navigation_util.dart`** exposing a `navigate.pop()` helper.
   This example ships a minimal one using `GlobalKey<NavigatorState>`.
4. **Wire `rootNavigatorKey`** into `MaterialApp.navigatorKey` so
   `navigate.pop()` can reach the active navigator.
5. **Add `mcp_toolkit` to pubspec** under `dependencies:`.
6. **Fill `docs/roveflow/scenarios.md`** with real cold-setup waypoints.

## Known gaps (findings from this dogfood — track for Phase 2)

- The bundled `mcp_interaction_tools.dart` has a literal `<your_app>`
  placeholder. `roveflow init` does not substitute it with the
  pubspec's package name. Manual fix required today.
- The skill assumes `navigate.pop()` exists. New Flutter apps don't have
  it — adopters must create a `navigation_util.dart` stub or adapt the
  tool. This example ships that stub at
  `lib/core/general_helpers/utils/navigation_util.dart` as a reference.

## Run the smoke test

Once a simulator is booted and the app reaches the counter screen:

```
/roveflow --only=cold-setup
```

in Claude Code. The orchestrator will dispatch a `roveflow-runner` and
emit a session recording at `docs/roveflow/runs/<timestamp>/`.
